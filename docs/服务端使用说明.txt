我带过的最差一届 · 房间服务器 使用说明
=========================================

一、运行环境
- Windows 10 / 11，64 位
- 不需要安装 .NET 运行时，exe 已自带（.NET 8 自包含单文件）
- 建议放在一个独立文件夹里运行，不要放进游戏目录

二、启动
1. 双击 WceRoomServer.exe。
2. 首次运行如弹出 Windows 防火墙提示，请点“允许访问”
   （需要放行 TCP 8080，以及 UDP 7100-7299 中继端口）。
3. 窗口标题显示“我带过的最差一届 · 自定义房间服务器”，说明已启动成功。
4. 面板顶部会显示“服务端地址”，例如 http://192.168.1.5:8080，
   把这个地址告诉玩家，填进游戏弹窗即可。

三、面板功能
- 顶部：服务端地址（点“复制”一键复制）、复制 / 设置 / 关于 按钮
- 统计卡：在线房间 / 在线玩家 / 注册账号
- 房间列表：房间名、主机、加入码、人数、状态、最后心跳
  · 选中一行点“关闭选中房间”，会把该房间内所有玩家断开并踢回登录界面（约 5 秒内生效）
  · 双击某行可复制加入码
- 玩家账号：当前在线的玩家（服务器不写硬盘，重启后需玩家重新注册）
- 运行日志：实时显示 API 请求与中继状态，排障时主要看这里
- 底部状态栏：最后刷新时间、端口、心跳超时；列表每 2 秒自动刷新

四、设置（点右上角“设置”）
可直接修改并保存到 server-config.json，保存后中继相关设置立即生效，新房间即按新配置分配：

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| serverName | 服务器显示名 | 我带过的最差一届 自定义房间服务器 |
| port | API 端口，修改后需重启 | 8080 |
| bind | 监听地址，0.0.0.0 为所有网卡 | 0.0.0.0 |
| roomTtlSeconds | 房间心跳超时，超时自动下线 | 30 |
| maxPlayersPerRoom | 单房间最大人数 | 6 |
| maxRooms | 最大房间数 | 200 |
| relayEnabled | 是否启用 UDP 中继 | true |
| relayHost | 中继对外地址，留空自动取本机内网 IPv4 | 空 |
| relayPortStart | 中继端口起始值，每个房间占一个 | 7100 |
| relayPortCount | 中继端口数量（决定同时可开房间数上限） | 200 |

五、中继模式（默认开启，推荐）
- 房主和玩家都主动连接服务器，由服务器转发游戏数据，双方都不需要做端口映射
- 服务器只需放行 TCP 8080 + UDP 7100-7299
- 公网部署时，务必把 relayHost 填成服务器的公网 IP 或域名，
  否则客户端会拿到内网地址，公网玩家连不上
- 代价：比直连多一跳，延迟增加约 10-30ms；服务器带宽占用随房间数上升

六、直连模式（relayEnabled=false）
- 数据不经过服务器，房主需要自己开放 UDP 游戏端口（默认 6565）并做路由器端口映射
- 此时房主在游戏内点“创建房间”会被要求填写外网地址，填写后自动保存到客户端 CustomServer.cfg
- 适合服务器带宽紧张、或双方网络条件很好的场景

七、放到公网服务器上
1. 把整个“服务端”文件夹上传到服务器（Windows Server 也可以，需 x64）
2. 云服务器安全组 / 防火墙放行 TCP 8080、UDP 7100-7299（按 relayPortCount 实际范围）
3. 打开面板“设置”，把 relayHost 改成公网 IP 或域名并保存
4. 把 http://公网IP:8080 发给玩家
5. 如需长期运行，可用“任务计划程序”设置开机自动启动

八、常见问题
- 玩家提示“服务器连接失败”：确认 exe 在运行、地址端口正确、8080 已放行；
  局域网内不要用 127.0.0.1，要用服务器内网 IP
- 玩家能看到房间但进不去：检查 UDP 7100-7299 是否放行，以及 relayHost 是否填对
- 房间列表为空：房主需要先在游戏里成功“创建房间”，服务器才会收到上报
- 房间莫名消失：多为房主游戏关闭或心跳超时（默认 30 秒）
- 关闭房间后玩家没掉线：房主游戏未运行或心跳网络异常，属正常兜底逻辑的延迟
- 日志里大量 404：通常是玩家退出后残留心跳，属正常现象
- 服务端重启：所有房间与账号清空，玩家需重新进游戏注册
